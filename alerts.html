影響 中 2026-10-09 承認 ・ Anthropic（Claude API）

Anthropic利用ポリシー改定：院内の下書き・要約は要件外と明記

Usage Policy

11月12日発効。有資格者の事前確認とAI利用の開示が要るのは、診断・治療の提案、症状や検査結果の解釈、受診の優先順位付けなど、高リスクの助言を個人に届けるか判断に使うとき。それ自体が高リスクの助言ではない院内の下書き・要約・分析は対象外と明記された。特定の業種を一律に禁じないことも明記。

要確認: 医師の診察内容の文字起こし・カルテの下書き・要約は、対象外と読めます（解釈）。AIが診断・処方・優先順位を提案し、それを患者に届けたり判断に使ったりする場合は、11月12日までに、有資格者が事前に確認する流れと、本人にAIの利用を伝える方法を確かめてください。

承認メモ: 院内での文字起こしやカルテの下書き・要約は、要件の対象外と読めます。AIの提案を患者に届けたり判断に使ったりするときは、有資格者の事前確認と、AIを使ったことの開示が必要です。

影響 中 2026-10-09 承認 ・ Google（Gemini API / Google Cloud）

Deep Researchエージェントは7日間データ保持、無効化不可と明記

Gemini Enterprise Agent Platform データ保持ゼロ／トレーニングの制限（旧 Vertex AI データガバナンス）

データ保持ゼロの例外として、Deep Researchエージェントの利用時は、プロンプト・検索結果・生成画像などのセッションデータを、Interactions API経由で7日間保存する旨が追記された。保存時は暗号化され、期限前に顧客が削除することもできるが、この保持は無効化できない。同エージェントに患者情報を入力する場合は、ゼロデータ保持を前提にできない。

要確認: 情報システム担当が、院内でDeep Researchエージェント（Interactions API）を利用しているか確認する。利用している場合は、患者情報を入力しない運用にするか、7日間保持と手動削除の手順を安全管理の文書・委託先評価に反映する。7日間保存されるデータの保存地、人間によるレビューの有無、学習への利用の有無を、Googleの資料または契約（Cloud Data Processing Addendum等）で確認する。

承認メモ: Deep Research エージェントは、ゼロデータ保持を申し込んでいても最長7日保存されます（期限前に削除はできますが、保存そのものは止められません）。患者情報を入れる場合は、安全管理の文書に反映してください。

影響 中 2026-10-01 承認 ・ AWS（Amazon Bedrock）

Bedrock: GPT-6 Sol/Lunaも不正検知で入出力を最大30日保存

Bedrock の不正利用検知（入出力を保存するモデルの一覧）

不正利用検知のため入出力を保存し得るモデル一覧に、OpenAI GPT-6 SolとGPT-6 Lunaが追加されました。これらのモデルでは、分類器が不審と判定した通信が最大30日保存されます。患者情報を含む入力が保存対象になり得るため、医療機関にとってはデータ保護上の条件が厳しくなる変更です。完全なゼロデータ保持（ZDR）は、対象となる顧客がAWSの担当チームに申請できると書かれています。

要確認: GPT-6 SolまたはGPT-6 Lunaを利用中、または利用予定かを情報システム担当が確認してください。該当する場合は、最大30日保存を前提として安全管理の説明（リスク評価・委託先管理）を見直すか、AWSの担当チームに完全ZDRの適格性と申請手続きを照会してください。あわせて、保存データの保存地域と、人間によるレビューの有無を確認してください。

影響 中 2026-10-01 承認 ・ OpenAI（API / ChatGPT Enterprise）

データ所在地の対応更新：GPT-6.1 Sol等は日本リージョン非対応

API データ管理ガイド

データレジデンシーの対応表が更新された。EUではGPT-6系でFlex・Batch処理も使えるようになった。一方、新モデルGPT-6.1 Solは米国とEUのみ、Ultrafastモードは米国とグローバル処理のみの対応と明記された。日本国内での保存・処理を条件とする医療機関は、このモデル・モードを選ぶと国内処理にならない可能性がある。学習利用・保持期間の記載に変更は見当たらない。

要確認: 情報システム担当は、次の3点を確認する。①自院または委託先ベンダーが日本のデータレジデンシーを使っている場合、GPT-6.1 SolやUltrafastモード・Fastモードを使っていないか、今後切り替える予定がないか。②公式ページの「Support by region」の表で、日本リージョンの対応モデル・処理モード（とくにBatches）が変わっていないか。差分で削除された2か所の一覧がどの地域のものかも確認する。③国内処理を契約・安全管理上の条件にしている場合は、ベンダーとの取り決め（利用するモデル・モードの固定）を見直す。
